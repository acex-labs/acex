## [6.23.0] - 2026-09-30

### Added
- [**breaking**] Split node status into admin_status and provision_status ([#292](https://github.com/acex-labs/acex/pull/292)) ([a268351](https://github.com/acex-labs/acex/commit/a268351b4b59605c712e5c2a1795c90060684265))

    > Node.status is replaced by two fields:
    >
    > - admin_status: operator intent (planned | active | decommissioned).
    >   The old "init" value is dropped in favour of provision_status.
    > - provision_status: where the device is in the provisioning lifecycle
    >   (unprovisioned | adopted | pending | bootstrapping | provisioning |
    >   provisioned | failed). Set by the provisioning flow; "adopted" marks
    >   brownfield devices brought under management.
    >
    > Telemetry and collection agent match rules get the same two fields.
    > MCP tools, CLI, client example and csv_sync_nodes are updated; the CSV
    > import marks active devices as adopted.
    >
    > Migration c7d2e9f1a3b4 maps existing data: active -> adopted, others ->
    > unprovisioned, init -> planned.


### Fixed
- Install devkit after poetry to ensure local version wins ([#290](https://github.com/acex-labs/acex/pull/290)) ([73cbbb2](https://github.com/acex-labs/acex/commit/73cbbb24279c701101c999fa29f70fa5c872e5cc))

    > poetry resolves acex-devkit from PyPI (2.8.0) as a transitive dep when
    > installing acex-client, overwriting the pip install of /deps/devkit.
    > Moving pip install /deps/devkit to after poetry install ensures the
    > local source (2.9.0 with AgentNodeSet) is what ends up installed.
